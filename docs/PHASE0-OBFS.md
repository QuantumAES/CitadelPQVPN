## 1. Назначение и происхождение дизайна

L1 (obfs) — симметричный слой на pre-shared key, который заворачивает датаграммы QUIC так, чтобы:
1. убрать DPI-инварианты QUIC (поле версии, форму long-header, фиксированные биты);
2. дать **probe-resistance** — без знания PSK сервер неотличим от закрытого порта / decoy;
3. рандомизировать длину (анти-fingerprint по размеру);
4. поддержать **миграцию соединения** (смена 4-tuple) на уровне obfs.

**Происхождение:** конструкция следует линии **Shadowsocks-2022 (SIP022)** — симметричный AEAD-обёртка с per-session ключом и зашифрованным заголовком сессии. В отличие от obfs4 здесь **нет obfs-уровневого Диффи-Хеллмана** (а значит, не нужен Elligator2): настоящий обмен ключами происходит внутри, в QUIC/TLS 1.3 (L2). L1 — чисто симметричный, на PSK.

> **Важно:** L1 — это обфускация + анти-зондирование, а **не** второй слой «настоящей» конфиденциальности. Реальная криптостойкость и PFS обеспечиваются L2 (гибридный TLS 1.3 over QUIC). L1 не должен рассматриваться как замена L2.

## 2. Иерархия ключей и KDF

Единственный долговременный секрет — `PSK_master` (32 байта), раздаётся вне канала (в подписке/конфиге, см. §8). Из него **доменно-разделёнными** контекстами BLAKE3 выводятся независимые ключи:

```
PSK_obf      = BLAKE3.derive_key("CitadelPQVPN/obfs/v1/psk-obf",  PSK_master)        # для L1 (этот документ)
PSK_tls_auth = BLAKE3.derive_key("CitadelPQVPN/tls/v1/psk-auth",  PSK_master)        # для L2-аутентификации (см. AUTH-ALTERNATIVES.md)
```

Внутри L1 — ещё два ключа:

```
K_hdr            = BLAKE3.derive_key("CitadelPQVPN/obfs/v1/header",  PSK_obf)             # 32 байта; шифрует заголовок сессии
K_sess(sid)      = BLAKE3.derive_key("CitadelPQVPN/obfs/v1/session", PSK_obf || sid)      # 32 байта; ключ AEAD тела, per-session
```

- `BLAKE3.derive_key(context, key_material)` — режим key-derivation BLAKE3: `context` — фиксированная строка доменного разделения, `key_material` — входной материал. Выход 32 байта.
- `sid` (session_id) — 8 байт. **Каждое направление имеет свой sid** (клиент выбирает `csid`, сервер — `ssid`), поэтому пространства nonce независимы и не пересекаются.
- `K_hdr` не зависит от сессии (одинаков для всех пакетов сервера) — это допустимо, т.к. заголовок шифруется keystream'ом на уникальном per-packet nonce (§4).

## 3. Формат пакета (на проводе)

Каждая UDP-датаграмма L0 несёт ровно один obfs-пакет:

```
 байт-оффсет   размер   поле
 ───────────   ──────   ───────────────────────────────────────────────────────────
 0             12       nonce_pkt           случайные 12 байт (на каждый пакет)
 12            16       enc_header          = (sid(8) ‖ packet_id(8,BE)) XOR KS_hdr
 28            var      aead_body           = ChaCha20Poly1305(K_sess(sid), body_nonce,
                                               AAD = nonce_pkt ‖ enc_header)( inner_plaintext )
                                             = ciphertext(len(inner)) ‖ tag(16)
```

```
┌────────────────────────────────────────────────────────────────────────────┐
│ nonce_pkt (12, открыто, случайно) │ enc_header (16, XOR-шифр) │ aead_body ... │
└────────────────────────────────────────────────────────────────────────────┘
                                                                  ▲
                                          ciphertext(inner) ‖ Poly1305 tag(16) ┘
```

- **Минимальный размер пакета** (DATA, нулевой padding, пустой QUIC-payload): 28 + (3 + 16) = **47 байт**.
- Никаких полей в открытом виде, кроме `nonce_pkt` (он случаен) → внешне поток неотличим от случайного.

### 3.1 `body_nonce`
```
body_nonce(packet_id) = 0x00 0x00 0x00 0x00 ‖ packet_id (8 байт, big-endian)   # 12 байт
```
Уникальность: `K_sess` зависит от `sid`, а `packet_id` монотонно растёт в пределах направления → пара (ключ, nonce) никогда не повторяется.

### 3.2 Шифрование заголовка (`enc_header`)
```
KS_hdr     = ChaCha20(key=K_hdr, nonce=nonce_pkt, counter=0)[0 .. 16]     # первые 16 байт keystream
enc_header = (sid ‖ packet_id_BE) XOR KS_hdr
```
- IV для ChaCha20 в формате OpenSSL/`cryptography`/`aws-lc-rs`: `counter(4 байта LE) ‖ nonce(12 байт)` → здесь `00000000 ‖ nonce_pkt`.
- Заголовок **малеабелен** (XOR), но это безопасно: `enc_header` входит в AAD тела (§3), поэтому любая его модификация ломает проверку тега AEAD → пакет отбрасывается. Подмена `sid` приведёт лишь к неверному `K_sess` → тег не сойдётся → drop.

## 4. `inner_plaintext` — формат по типам

```
inner_plaintext = type(1)
                ‖ timestamp(8, BE)      ← только если type ∈ {INIT_C, INIT_S}
                ‖ echo_csid(8)          ← только если type == INIT_S
                ‖ pad_len(2, BE) ‖ padding(pad_len)
                ‖ quic_payload(остаток)
```

| type | значение | назначение | доп. поля |
|------|----------|------------|-----------|
| `0x01` | `INIT_C` | первый пакет клиента (устанавливает сессию `csid`) | `timestamp` |
| `0x02` | `INIT_S` | первый пакет сервера (ответ, сессия `ssid`) | `timestamp`, `echo_csid` |
| `0x03` | `DATA`   | все последующие пакеты любой стороны | — |
| `0x04` | `PAD`    | chaff/dummy для тайминг-шейпинга (§7); `quic_payload` пуст, приёмник отбрасывает | — |

- `timestamp` — Unix-время (секунды) отправителя; анти-replay-окно (§6).
- `echo_csid` — сервер возвращает `csid` клиента (подтверждает, что расшифровал INIT_C; привязывает ответ к сессии клиента).
- `quic_payload` — байты датаграммы QUIC (L0/L2), как есть.

## 5. Жизненный цикл сессии и миграция

1. **Старт (клиент):** генерирует `csid` (8 случайных байт), `packet_id := 0`. Первый пакет — `INIT_C` с `timestamp`. `packet_id` инкрементируется на каждый отправленный пакет.
2. **Приём INIT_C (сервер):** проверяет окно `timestamp` (§6). При успехе создаёт сессию по `csid`, выбирает `ssid`, отвечает `INIT_S` (echo `csid`), ведёт свой `packet_id` для направления S→C.
3. **Стационар:** обе стороны шлют `DATA`, демультиплексирование — **по `sid` из `enc_header`** (не по 4-tuple).
4. **Миграция (смена сети):** клиент сохраняет `csid` и продолжает слать пакеты с нового адреса. Сервер демультиплексирует по `csid`, и **только после успешной проверки AEAD** обновляет remote-адрес сессии (анти-спуфинг — аналог path-validation; внутри ещё и QUIC делает свою path-validation). Слепой атакующий не может «увести» сессию: нет PSK → нет валидного тега; повтор старых пакетов отбивается окном replay.

## 6. Анти-replay и probe-resistance (нормативные правила)

**Probe-resistance:**
- Любой пакет, чьё тело AEAD **не проходит проверку**, отбрасывается **без ответа**. Опционально — перенаправляется на decoy-обработчик (для TCP/443-fallback: отдать правдоподобный HTTPS-ответ, чтобы порт не выглядел «молчащим»).
- Пробер без `PSK_obf` не может изготовить валидный тег → сервер молчит. Единственное наблюдаемое — «сервер принимает UDP» (как любой UDP-сервис).

**Анти-replay:**
- **INIT-пакеты:** `|now − timestamp| ≤ WINDOW` (рекомендация: `WINDOW = 30 c`). Вне окна → drop. Плюс кэш недавно принятых `csid` в пределах окна (защита от повтора установочного пакета до создания сессии).
- **Все пакеты в рамках сессии:** скользящее окно по `packet_id` (рекомендация: ширина 1024). `packet_id` уже виденный или «слишком старый» → drop. Это же исключает повтор nonce AEAD.

## 7. Padding, тайминг-шейпинг и MTU

**Ось размера (анти-fingerprint по длине):**
- `padding` рандомизирует длину пакета (анти-fingerprint). Для **INIT** рекомендуется больший случайный padding (размер первого пакета — сильный отпечаток). Профиль паддинга — конфигурируемый (`none` / `random[0..N]` / `bucketed` для приближения к константному размеру).
- **Реализовано (bucketed, default для DATA):** размер пакета на проводе добивается до ближайшего бакета из `{256, 512, 1024, 1280}` (`Citadel_obfs::DEFAULT_BUCKETS`). Функция `pad_len_for(policy, quic_len)` считает добавочные байты от `FRAMING_OVERHEAD(47) + quic_len` до ближайшего бакета ≥ wire; свыше наибольшего бакета — без паддинга (в пределах MTU не случается, см. `initial_mtu=1200`). Это схлопывает распределение длин DATA в ≤4 значения (закрывает размерную ось I5). Содержимое padding — нули (внутри AEAD; на проводе — псевдослучайный шифртекст). Приёмная сторона срезает padding в `parse_inner` по полю `pad_len` — формат на проводе не меняется.

**Ось времени (анти-корреляция по таймингу, DAITA-стиль):**
- **Реализовано (env-gated, default off):** при `Pacing::Slotted` исходящие пакеты не пишутся синхронно, а буферизуются в bounded-очередь (cap 1024, переполнение → дроп = потеря UDP, QUIC ретрансмитит) и выпускаются фоновым pacer'ом по **слот-сетке** (`slot`, до `burst` реальных пакетов за тик) — это квантует межпакетные интервалы в сетку, скрывая микро-тайминг приложения.
- **Chaff (`TYPE_PAD`):** в пустые слоты подмешиваются dummy-пакеты, паддятся до случайного бакета (распределение длин = реальному трафику). Политики: `Off` / `Adaptive{window}` (chaff только пока реальный трафик был в окне — WTF-PAD-стиль, маскирует паузы/хвосты, не гонит вечный chaff в простое) / `Always` (constant-rate, для high-threat). Приёмник распознаёт `TYPE_PAD` и отбрасывает до QUIC.
- **Конфиг:** `Citadel_PACING` = `off`(default) | `on` | `<slot_ms>:<burst>:<off|adaptive|always>`. По умолчанию выключено: пейсинг торгует латентностью/трафиком, включается под угрозу анализа таймингов.
- **Открыто:** копирование реального распределения размеров в chaff (сейчас равномерно по бакетам), пейсинг входящего направления, ML-информированные защиты (полный DAITA/Tamaraw).
- **Накладные расходы поверх `quic_payload`:**
  - `DATA`: **47 байт** + padding (12 nonce + 16 enc_header + 16 tag + 1 type + 2 pad_len).
  - `INIT_C`: 55 байт + padding; `INIT_S`: 63 байта + padding (амортизируется — по одному на направление).
- Это уменьшает полезный inner-MTU туннеля → учитывать в DPLPMTUD/MSS-clamp (SPEC §6, §11). Опциональный **compact-mode** (демультиплексирование по 4-tuple, без `enc_header`) экономит 16 байт, но теряет бесшовную миграцию — не использовать там, где важна смена сети.

## 8. Распространение и ротация PSK

- `PSK_master` доставляется в подписке/конфиге по аутентифицированному каналу (вне области L1).
- **Ротация:** поддерживаются две одновременные эпохи (`current` + `previous`). Сервер при неуспехе с `K_hdr(current)` пробует `K_hdr(previous)` (≤2 попытки AEAD, дёшево). Бесшовно для клиентов на переходе.
- Компрометация конфига одного клиента раскрывает `PSK_obf` сервера → требуется ротация. Это осознанный компромисс консьюмерской модели (см. SPEC §1, доверие).

## 11. Открытые параметры (зафиксировать на M3)
- `WINDOW` анти-replay (по умолчанию 30 c) и ширина окна `packet_id` (1024).
- Профиль паддинга по умолчанию для consumer (баланс анти-анализ ↔ трафик).
- Decoy-обработчик для TCP/443-fallback (какой именно правдоподобный ответ).
- Длина `sid` (8 байт → 2⁶⁴ сессий на эпоху PSK; достаточно, но зафиксировать).
