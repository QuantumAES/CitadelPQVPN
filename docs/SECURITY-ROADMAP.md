# CitadelPQVPN — стратегия разработки после security-аудита

**Дата:** 2026-07-06 · **Основание:** аудит red-team/DevSecOps (см. память проекта `citadel-security-audit-2026-07`) · **Оптика:** инженерный триаж находок + пересборка дорожной карты.

Документ не заменяет `SPEC.md`/`THREAT-MODEL-STRIDE.md`, а надстраивает над ними приоритеты. Существующие роадмапы (`SPEC §12` M0–M7, `CLIENT-ARCH` C0–C6) остаются; здесь — как их пересеквенсировать в свете аудита.

---

## 0. Ре-базлайн статуса (честная метка «готовности»)

`SPEC §12` помечает M0–M7 как ✅. Аудит показал, что корректная метка — **PoC ✅ / production ❌**. Конкретно:

- **M4 (TCP-fallback)** — не production: канал держится на статическом общем PSK, без TLS/PQ/PFS (H1). SPEC обещает «QUIC-in-TCP» — не реализовано.
- **M7 (PQ-auth)** — не production: в дефолтном деплое выключена; при отсутствии pin деградирует в подпись над константой (H2).
- **M2 (kill-switch)** — сам SPEC честно держит 🟡; аудит подтверждает fail-open при крахе (M9).

**Вывод стратегии:** протокол — PoC-grade. Клиентский трек (C*) вырвался вперёд и «выглядит готовым к отгрузке», тогда как транспорт под ним имеет критическую дыру. **Правило:** никакой публичной/бета-экспозиции, пока не закрыт S0 (блокеры) и не проведён мини-аудит диффов.

Легенда: **Эффорт** S/M/L · **Wire** — ломает ли формат провода/тест-векторы · **Куда** — в какой этап садится.

**Ключевые расхождения с аудитом (добавленная инженерная ценность):**
1. **H1+M2+M3 — это один wire-ломающий релиз, не три.** Развёрнутых пользователей нет → ломаем формат один раз: QUIC-over-TCP + соль/увеличенный sid + регенерация PHASE0-векторов + правка спеки. Не размазывать сломы по релизам.
2. **M1/M4 переоценены аудитом** (гигиена/политика, не критикал) — но всё равно чинятся, дёшево.
3. **M5/M6/M9 — не новая работа: они уже C5/C6.** Аудит не изобрёл их, а провалидировал приоритет клиентского трека.
4. **H1-фикс — это упрощение, а не только «безопасность»:** после него единый QUIC-путь, obfs — чистая транспорт-обёртка (UDP или TCP), `Tunnel`-дуализм в control/pump уходит.

## 2. Предпосылки (Gate 0 — до старта security-трека)

Security-пуш на 40+ юнит + 15 docker-тестов без страховки = гарантированные регрессии. Поэтому **сначала**:

- **G0.1 CI.** Сейчас `.github/workflows` пуст (remote `QuantumAES/CitadelPQVPN` живой). Поднять workflow: `cargo test --workspace` + `cargo clippy -D warnings` (тулчейн 1.96) + прогон docker-харнеса. Без CI security-трек не ведётся.
- **G0.2 Чистое дерево.** Закоммитить in-flight (android/client/quic/helper + новый diag) до зелёного (workspace + docker 15/15). Security-фиксы должны стартовать с бисектируемого базлайна.
- **G0.3 Снимок wire.** Зафиксировать текущий формат/тест-векторы obfs — чтобы осознанно ломать их в S0.3.
- **G0.4 Fuzzing (опц., но к месту).** rustup стоит → завести `cargo-fuzz` на парсеры (obfs/masque) как гейт S0. Парсеры = поверхность атаки.

## 3. Обновлённая дорожная карта

### S0 — Блокеры релиза (гейт публичной/бета-экспозиции)
- **S0.1 (H2) fail-closed pinning.** Без pin — отказ (кроме `--insecure` dev-флага). ML-DSA: требовать активный pin + привязка к серту живой сессии, а не к провижининг-константе. *Тест:* негатив в харнесе (no-pin → refuse; чужой pin → refuse).
- **S0.2 (H3) анти-спуфинг.** Стопгэп: `rp_filter=1` + `iptables FORWARD -i tun ! -s pool -j DROP` в `server_setup_net`. Затем app-layer: `src == назначенный` в `Inbound::accept` + default-deny не-IPv4. *Тест:* спуфнутый src / IPv6 дропаются.
- **S0.3 (H1+M2+M3) унификация транспорта.** `AsyncUdpSocket`-over-TCP несёт настоящий QUIC(TLS1.3+hybrid); удалить `Tunnel::Tcp`-спецпуть. В этом же wire-ломающем релизе: per-session соль в `k_sess` (+ увеличить sid), регенерация PHASE0-векторов, привести SPEC (§7/§11 «QUIC-in-TCP», §4 anti-replay) в соответствие. *Тест:* fallback показывает PQ-хендшейк; PSK-only не расшифровывает трафик; TEST 11 переписан.

**Критерий выхода S0:** docker-харнес зелёный на новых негативах; fallback криптографически эквивалентен UDP-пути; мини-аудит диффов.

### S1 — Хардненинг до широкой беты
- **S1.1 (M4)** PQ-only: installer default `KX=pq`; клиент ассертит negotiated-группу = гибрид под pq-политикой; `all` — только явное окно миграции.
- **S1.2 (M1)** валидация входов + граница app↔helper: `dns`=один IP, `routes`=CIDR (при импорте И в helper); не интерполировать неподтверждённые строки в конфиги.
- **S1.3 (M7)** zeroize на PSK/seed/токены/vault-key/расшифрованные профили.
- **S1.4 (M8)** приватность лога: opt-in/ring-only/в vault; очистка на disconnect.
- **S1.5 (L2–L4)** supply-chain: pin Docker-инсталла + digest-pin base-image; reproducible builds; cosign в дополнение к minisign; `read_only: true` + tmpfs у контейнера.

### S2 — Свёрнуто в клиентский трек (уже запланировано)
- **C5 (идентичность)** = продакшенизация auth: двухслойные epoch-токены + issuer-registry (закрывает **M5** per-user + **M6** persistent double-spend); завести токены+ML-DSA в installer.
- **C6 (упаковка)** = fail-closed kill-switch (desktop-firewall + Android `setBlocking`/always-on, закрывает **M9**) + нотаризация + **Argon2id** для vault (L1).
  - **Известное ограничение (2026-07-12, боевой тест APK):** реконнект при смене сети (toggle WiFi) работает только на **переднем плане**. Причина — детект-сети (NetworkCallback) и цикл реконнекта привязаны к Activity/Flutter-движку; при уходе app в фон (а именно так пользователь переключает WiFi) Activity гасится → событие сети теряется, движок не крутит ретраи, и передний план это не восстанавливает (событие уже прошло). Фикс архитектурный и входит в C6 «always-on»: увести детект-сети + реконнект (и сам движок) в **нативный `CitadelVpnService`** (переживает смерть Activity) либо в фоновый Flutter-isolate. Тестируется только на устройстве. Первый Dart-driven срез (2026-07-05) закрывает foreground-случай.

### C7 — Admin-plane v2: выдача/отзыв доступа по туннелю (спроектирован 2026-07-17; заменяет SSH-путь GUI из C5.5)

**Мотивация.** Управление реестром абонентов из GUI сейчас идёт по SSH (`api/admin.rs` → russh → `citadel-token registry` на сервере): (а) в GUI вводятся **root-креды сервера** — чрезмерная привилегия для операции «добавить абонента» и лишний долгоживущий секрет в приложении; (б) host-key — TOFU без персиста (MITM first-use); (в) russh не собирается в мобильный APK → функция desktop-only; (г) UX — отдельный экран с SSH-полями вместо меню серверов. Одновременно «админская ссылка» инсталлера — обычная абонентская: понятия «мастер-ссылка» в формате кред нет, роль админа держится на знании SSH-пароля.

**Дизайн — admin-роль поверх существующего PQ-TLS канала issuer** (та же машинерия, что S2.1/A1 + Layer-1):

1. **Admin-идентичность.** Инсталлер генерит отдельный Ed25519 `admin.seed`; на сервере (том issuer) остаётся ТОЛЬКО pub (`admin_id`), seed уходит в мастер-ссылку. Формат кред **v3**: поля `admin_seed` (+ `admin_port`, дефолт 7001) с `#[serde(default)]` → v2-ссылки продолжают читаться (admin_seed=None). Мастер-ссылка = обычная абонентская + admin_seed; клиентские ссылки этих полей **не несут**.
2. **Протокол.** Тот же PQ-TLS (пин из ссылки, X25519MLKEM768): после серверного challenge админ отвечает кадром `0x01 ‖ pub(32) ‖ sig(64)`, где `sig = Ed25519(admin_seed, "citadel-admin/v1" ‖ challenge ‖ EKM)`, EKM — TLS exporter сессии. Domain-separation отделяет admin-auth от Layer-1-auth (кросс-протокольный replay подписи невозможен: ключи разные И контексты разные), EKM привязывает подпись к конкретной TLS-сессии (channel binding — закрывает A3-класс для admin-плоскости). Абонентский кадр остаётся 96 Б → wire аддитивен, старые клиенты не затронуты. Дальше — CBOR-кадры команд `list` / `add(client_id, valid_until)` / `revoke(client_id)`; правки реестра — существующими атомарными `registry_apply_add/revoke` (вынести из main.rs в lib).
3. **Достижимость — только из туннеля.** Admin-listener на отдельном порту (:7001) **без публикации наружу**: compose-порт не публикуется; exit добавляет DNAT `10.7.0.1:7001 → issuer:7001` только для пакетов с `-i Citadel0`. Итого admin-плоскость не видна WAN-сканам, а команды идут в **трёх** слоях защиты: PQ-QUIC туннель → PQ-TLS с пином → admin-подпись. Публичным остаётся только :7000 (token-fetch, ему это необходимо: токен нужен ДО туннеля).
4. **Выдача доступа новому абоненту — целиком на устройстве админа.** Ядро генерит свежий `client_seed` (CSPRNG) → по admin-каналу регистрирует только pub (client_id) → клиентскую ссылку собирает **локально** (бандл админа минус admin_seed, с новым client_seed) → QR/копирование. Issuer seed нового абонента не видит (модель C5.4b сохранена). Метки «кому выдано» — локально в vault админа, **не на сервере** (не заводим серверную БД деанонимизации).
5. **Enforcement — на сервере; UI-гейтинг — вторичен.** Пункт «Абоненты» рендерится только для admin-профиля (`isAdmin` = наличие admin_seed), но реальный барьер — проверка `admin_id` на issuer: клиентская ссылка не даёт admin-операций даже из модифицированного приложения.
6. **Все платформы.** Admin-клиент — тот же sync-rustls код, что `fetch_tokens` (`spawn_blocking`) → Android/iOS/десктопы без russh. SSH-экран (`AdminRegistryPage`) и russh-бэкенд `api/admin.rs` удаляются из app; russh остаётся только в `citadel_client::deploy` (C4, вне GUI). Break-glass — bootstrap-скрипт по SSH руками на сервер (как при установке).

**Этапы:**
- **C7.1 citadel-token: admin-протокол — ✅ (2026-07-17).** Registry-ops вынесены в `citadel_token::admin` (общие для CLI и канала); отдельный admin-listener (`Citadel_ADMIN_LISTEN`, не смешан с :7000 — там по-прежнему только 96-байтовый Layer-1 кадр) с `AdminServer::serve_conn`: challenge → кадр `0x01‖pub‖sig` (домен `citadel-admin/v1` + EKM `EXPORTER-citadel-admin/v1`) → CBOR-команды; чтение `admin_id`/`admin.client_id` на каждую операцию (ротация без рестарта); throttle 1с на провал auth, отказ без ack (не оракул); `AdminClient` (sync, для C7.3). *Тесты (9):* e2e list/add/revoke + lockout-guard + дефолтный срок + «прошлое → отказ»; негативы — чужой ключ, отсутствие admin_id (secure default), Layer-1-кадр (даже если ключ = admin_id), подпись без домена/без EKM/чужой EKM/подделка; CBOR roundtrip; parse_registry.
- **C7.2 креды v3 + installer — ✅ (2026-07-17).** `admin_seed`/`admin_port` в `CredentialBundle`/`CredentialLink` (`#[serde(default)]`, `BUNDLE_VERSION=3`, чтение v2..=v3 → старые ссылки живы; zeroize admin_seed; `is_admin()`/`admin_port()`); `citadel-linkgen --admin-seed/--admin-port` (+предупреждение о мастер-ссылке). Data-plane: `Inbound::with_admin` пропускает TCP к `(admin_vip, admin_port)` мимо F2 (после анти-спуфинга src) → ядро DNAT'ит на issuer; `ip::tcp_dport`; `pump` получил `admin_dst`; m1 читает `Citadel_ADMIN_VIP/PORT`, ставит DNAT `-i Citadel0` (наружу порт не публикуется). Инсталлер: keygen `admin.seed`, `admin_id`+`admin.client_id` на том issuer, `Citadel_ADMIN_LISTEN` на issuer, VIP/DNAT (резолв issuer по docker-DNS) на exit, отдельные мастер- и клиент-ссылки. `ADMIN_VIP` — константа (= шлюз `Citadel_TUN_ADDR`, инвариант деплоя). *Тесты (+3):* admin-поля round-trip + accessors, **v2-ссылка парсится под v3** (доказывает map-кодирование ciborium), data-plane admin-исключение (только TCP+точный порт+VIP+назначенный src). *Отложено в C7.5:* nmap-негатив «порт снаружи закрыт» — в docker-харнесе. *Известное огранич.:* DNAT резолвит issuer-IP один раз на старте exit — рестарт issuer с новым IP требует рестарта exit (как и pin-файлы).
- **C7.3 citadel-client: admin-ядро + минт ссылок — ✅ (2026-07-18).** Модуль `citadel_client::admin` (async поверх `spawn_blocking`/`citadel_token::admin`, БЕЗ cfg-гейта → все платформы, в отличие от russh): `admin_list`/`admin_revoke`/`admin_issue` выводят адрес (`ADMIN_VIP:admin_port`), pin (`issuer_pin`) и `admin_seed` из МАСТЕР-ссылки — недоступны с клиентской (fail-closed). `build_subscriber_link` — чистая сборка клиентской ссылки: свежий CSPRNG-seed, admin-поля вырезаны (+zeroize old admin_seed). `admin_issue` = seed→client_id→сборка ссылки (ДО регистрации)→`add` по каналу. Хелперы `parse_client_id`/`parse_valid_until`. Vault: `IssuedRecord` + `add_issued`/`list_issued`/`remove_issued` (метки «кому выдал» — только на устройстве админа; `#[serde(default)]` → старые vault читаются). *Тесты (+6):* e2e issue→list→revoke против in-process issuer admin-сервера, отказ на чужой admin-seed, strip-admin+swap-seed минта, вывод conn-параметров + отказ не-мастер, parse_valid_until, vault issued upsert/roundtrip. *Прим.:* admin-канал достижим только из-под поднятого туннеля (ADMIN_VIP=шлюз /16 → on-link и в split-tunnel). Каждая операция — самодостаточный connect→op→close.
