# CitadelPQVPN — стратегия разработки после security-аудита

**Дата:** 2026-07-06 · **Основание:** аудит red-team/DevSecOps (см. память проекта `citadel-security-audit-2026-07`) · **Оптика:** инженерный триаж находок + пересборка дорожной карты.

Документ не заменяет `SPEC.md`/`THREAT-MODEL-STRIDE.md`, а надстраивает над ними приоритеты. Существующие роадмапы (`SPEC §12` M0–M7, `CLIENT-ARCH` C0–C6) остаются; здесь — как их пересеквенсировать в свете аудита.

---

## 0. Ре-базлайн статуса (честная метка «готовности»)

`SPEC §12` помечает M0–M7 как ✅. Аудит показал, что корректная метка — **PoC ✅ / production ❌**. Конкретно:

- **M4 (TCP-fallback)** — не production: канал держится на статическом общем PSK, без TLS/PQ/PFS (H1). SPEC обещает «QUIC-in-TCP» — не реализовано.
- **M7 (PQ-auth)** — не production: в дефолтном деплое выключена; при отсутствии pin деградирует в подпись над константой (H2).
- **M2 (kill-switch)** — сам SPEC честно держит 🟡; аудит подтверждает fail-open при крахе (M9).

**Вывод стратегии:** протокол — PoC-grade. Клиентский трек (C*) вырвался вперёд и «выглядит готовым к отгрузке», тогда как транспорт под ним имеет критическую дыру. **Правило:** никакой публичной/бета-экспозиции, пока не закрыт S0 (блокеры) и не проведён мини-аудит диффов.

## 1. Инженерный триаж аудита

Легенда: **Эффорт** S/M/L · **Wire** — ломает ли формат провода/тест-векторы · **Куда** — в какой этап садится.

| # | Находка | Вердикт инженера | Эффорт | Wire | Куда |
|---|---|---|---|---|---|
| **H1** | TCP-fallback = статический PSK, без PFS/PQ | **Подтверждаю блокер.** Правильный фикс — не «второй протокол», а `AsyncUdpSocket` поверх TCP, несущий тот же QUIC(TLS1.3+hybrid). Схлопывает дублирование `Tunnel::Tcp` → чистый выигрыш. | L | **да** | S0.3 |
| **H2** | Insecure-by-default при отсутствии pin | **Подтверждаю блокер, но дёшево.** fail-closed + привязка ML-DSA к живому серту. | S | нет | S0.1 |
| **H3** | Нет фильтра inner-source → спуфинг; IPv6 fail-open | **Подтверждаю.** IPv4-спуфинг — острый; IPv6 — латентный (в дефолте IPv6-forward off). Есть дешёвый стопгэп (rp_filter + `-s pool`). | S→M | нет | S0.2 |
| **M1** | dns/routes-инъекция из ссылки в root-helper | **Понижаю до гигиены.** Автор ссылки уже владеет коннектом (pin+psk+server) → мог бы задать свой резолвер легально. Реальная суть — граница app↔helper: helper не должен доверять строкам app. Фиксить, но не блокер. | S | нет | S1.2 |
| **M2** | obfs nonce-reuse (64-бит sid + общий PSK) | **Реальный дефект, но фикс ломает wire** (соль/16-байт sid) → **батчить с H1**. Дешёвый частичный митигейт сейчас: стартовать packet_id со случайного u64 (без слома формата). | S(частич)/M(полн) | да(полн) | S0.3 |
| **M3** | Нет anti-replay; SPEC обещает | **Сначала чинить СПЕКУ, не код.** Транспорт шлёт только TYPE_DATA; Phase-0 gate-хендшейк не нужен (лишняя поверхность). Probe-resistance держит AEAD-гейт. Replay-кэш — низкий приоритет. | S(спека) | нет | S0.3/S3 |
| **M4** | PQ-downgrade не форсится | **Понижаю: политика, не атака.** MITM не понизит pq-only клиента (TLS-транскрипт). Суть — installer `KX=all` + нет ассерта «группа=гибрид». Дёшево. | S | нет | S1.1 |
| **M5** | Дефолт без токенов/ML-DSA | **Не баг — посадка v1.** Bearer-link легитимен (как algo/wg), ЕСЛИ документирован. Апгрейд уже запланирован (C5). Переклассифицирую в roadmap-решение. | — | нет | C5 |
| **M6** | Double-spend per-exit, in-RAM | **Субсумируется C5** (epoch-registry на issuer). До C5 токенов в проде нет → moot. | — | нет | C5 |
| **M7** | Нет zeroize | Гигиена, дёшево. rustls/aws-lc свои ключи чистят; наши копии — нет. | S→M | нет | S1.3 |
| **M8** | Персистентный plaintext-лог клиента | Реальная приватностная дыра, дёшево. Прямо противоречит no-logs. | S | нет | S1.4 |
| **M9** | Нет fail-closed kill-switch | Реально; **уже в плане C6**. Нетривиально (переживать краш движка). | M | нет | C6 |
| L1–L5 | Argon2id / supply-chain / ro-rootfs / SPKI-pin / RSA-DoS | Хардненинг. Argon2id→C6; supply-chain→S1.5; SPKI-pin — при следующем сломе wire. | S each | — | S1.5/C6 |

**Ключевые расхождения с аудитом (добавленная инженерная ценность):**
1. **H1+M2+M3 — это один wire-ломающий релиз, не три.** Развёрнутых пользователей нет → ломаем формат один раз: QUIC-over-TCP + соль/увеличенный sid + регенерация PHASE0-векторов + правка спеки. Не размазывать сломы по релизам.
2. **M1/M4 переоценены аудитом** (гигиена/политика, не критикал) — но всё равно чинятся, дёшево.
3. **M5/M6/M9 — не новая работа: они уже C5/C6.** Аудит не изобрёл их, а провалидировал приоритет клиентского трека.
4. **H1-фикс — это упрощение, а не только «безопасность»:** после него единый QUIC-путь, obfs — чистая транспорт-обёртка (UDP или TCP), `Tunnel`-дуализм в control/pump уходит.

## 2. Предпосылки (Gate 0 — до старта security-трека)

Security-пуш на 40+ юнит + 15 docker-тестов без страховки = гарантированные регрессии. Поэтому **сначала**:

- **G0.1 CI.** Сейчас `.github/workflows` пуст (remote `QuantumAES/CitadelPQVPN` живой). Поднять workflow: `cargo test --workspace` + `cargo clippy -D warnings` (тулчейн 1.96) + прогон docker-харнеса. Без CI security-трек не ведётся.
- **G0.2 Чистое дерево.** Закоммитить in-flight (android/client/quic/helper + новый diag) до зелёного (workspace + docker 15/15). Security-фиксы должны стартовать с бисектируемого базлайна.
- **G0.3 Снимок wire.** Зафиксировать текущий формат/тест-векторы obfs — чтобы осознанно ломать их в S0.3.
- **G0.4 Fuzzing (опц., но к месту).** rustup стоит → завести `cargo-fuzz` на парсеры (obfs/masque) как гейт S0. Парсеры = поверхность атаки.

## 3. Обновлённая дорожная карта

### S0 — Блокеры релиза (гейт публичной/бета-экспозиции)
- **S0.1 (H2) fail-closed pinning.** Без pin — отказ (кроме `--insecure` dev-флага). ML-DSA: требовать активный pin + привязка к серту живой сессии, а не к провижининг-константе. *Тест:* негатив в харнесе (no-pin → refuse; чужой pin → refuse).
- **S0.2 (H3) анти-спуфинг.** Стопгэп: `rp_filter=1` + `iptables FORWARD -i tun ! -s pool -j DROP` в `server_setup_net`. Затем app-layer: `src == назначенный` в `Inbound::accept` + default-deny не-IPv4. *Тест:* спуфнутый src / IPv6 дропаются.
- **S0.3 (H1+M2+M3) унификация транспорта.** `AsyncUdpSocket`-over-TCP несёт настоящий QUIC(TLS1.3+hybrid); удалить `Tunnel::Tcp`-спецпуть. В этом же wire-ломающем релизе: per-session соль в `k_sess` (+ увеличить sid), регенерация PHASE0-векторов, привести SPEC (§7/§11 «QUIC-in-TCP», §4 anti-replay) в соответствие. *Тест:* fallback показывает PQ-хендшейк; PSK-only не расшифровывает трафик; TEST 11 переписан.

**Критерий выхода S0:** docker-харнес зелёный на новых негативах; fallback криптографически эквивалентен UDP-пути; мини-аудит диффов.

### S1 — Хардненинг до широкой беты
- **S1.1 (M4)** PQ-only: installer default `KX=pq`; клиент ассертит negotiated-группу = гибрид под pq-политикой; `all` — только явное окно миграции.
- **S1.2 (M1)** валидация входов + граница app↔helper: `dns`=один IP, `routes`=CIDR (при импорте И в helper); не интерполировать неподтверждённые строки в конфиги.
- **S1.3 (M7)** zeroize на PSK/seed/токены/vault-key/расшифрованные профили.
- **S1.4 (M8)** приватность лога: opt-in/ring-only/в vault; очистка на disconnect.
- **S1.5 (L2–L4)** supply-chain: pin Docker-инсталла + digest-pin base-image; reproducible builds; cosign в дополнение к minisign; `read_only: true` + tmpfs у контейнера.

### S2 — Свёрнуто в клиентский трек (уже запланировано)
- **C5 (идентичность)** = продакшенизация auth: двухслойные epoch-токены + issuer-registry (закрывает **M5** per-user + **M6** persistent double-spend); завести токены+ML-DSA в installer.
- **C6 (упаковка)** = fail-closed kill-switch (desktop-firewall + Android `setBlocking`/always-on, закрывает **M9**) + нотаризация + **Argon2id** для vault (L1).
  - **Известное ограничение (2026-07-12, боевой тест APK):** реконнект при смене сети (toggle WiFi) работает только на **переднем плане**. Причина — детект-сети (NetworkCallback) и цикл реконнекта привязаны к Activity/Flutter-движку; при уходе app в фон (а именно так пользователь переключает WiFi) Activity гасится → событие сети теряется, движок не крутит ретраи, и передний план это не восстанавливает (событие уже прошло). Фикс архитектурный и входит в C6 «always-on»: увести детект-сети + реконнект (и сам движок) в **нативный `CitadelVpnService`** (переживает смерть Activity) либо в фоновый Flutter-isolate. Тестируется только на устройстве. Первый Dart-driven срез (2026-07-05) закрывает foreground-случай.

### S3 — Сверка доков с кодом (непрерывно)
По мере фиксов приводить в соответствие claims: SPEC (QUIC-in-TCP, anti-replay, KX-policy), PHASE0 (векторы), creds (SPKI-pin vs blake3-DER), THREAT-MODEL (статусы S4/E1/kill-switch), CLIENT-ARCH.

## 4. Инженерные guardrails

- **Тест на каждый фикс.** Security-фикс без red→green теста не мёржится. Харнес растёт 15 → ~20+.
- **Один слом wire.** Все формат-ломающие изменения — только в S0.3. Не дробить.
- **Гейт экспозиции.** Публичный endpoint / бета-инвайты — только после S0-green + мини-аудит.
- **Инвариант «один движок».** После S0.3 — единый QUIC/TLS-путь; obfs = транспорт-обёртка (UDP|TCP), не параллельный протокол.
- **Честные метки.** `SPEC §12` перевести на «PoC ✅ / prod ⏳» по M4/M7; `THREAT-MODEL` S4 → в работе (S0.2).
- **Тулчейн-риск.** ML-DSA на `aws-lc-rs unstable` — пинить версии, следить за стабилизацией API.

## 5. Одной фразой

Протокол — PoC, а не продукт. **Заморозить расширение клиентской ширины, вставить security-гейт S0 (H1/H2/H3) перед любой экспозицией, батчить единственный слом wire в S0.3, а M5/M6/M9 добить штатными C5/C6.** Предусловие ко всему — CI и чистое дерево.
