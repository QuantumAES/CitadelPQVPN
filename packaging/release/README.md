# Релизные ключи подписи (CitadelPQVPN)

Здесь лежит **публичный** minisign-ключ, которым подписываются бинари релиза
(`citadel-m1`, `citadel-linkgen`). Установщик сервера (`install-citadel-server.sh`)
верифицирует скачанный бинарь этим ключом — это ядро supply-chain-защиты (§8).

- `citadel-release.pub` — публичный ключ (**коммитится**; вшивается в установщик).
- **Секретный** ключ (`citadel-release.key`) — password-protected, живёт **вне репозитория**
  (по умолчанию `~/.citadel/release/`, переопределяется `$CITADEL_RELEASE_KEY_DIR`) и
  **никогда не коммитится** (см. `.gitignore`).

## Первичная генерация (один раз, мейнтейнер)

```sh
tools/gen-release-key.sh          # интерактивно спросит пароль секрета
git add packaging/release/citadel-release.pub
```

Затем — офлайн-бэкап секрета (потеря = невозможно подписывать новые релизы;
компрометация = подпись вредоносного бинаря пройдёт verify на серверах).

## Подпись релиза

`tools/mk-release.sh` (шаг 2) собирает release-бинари, стрипает, жмёт zstd, считает
`sha256sums` и подписывает их секретным ключом. Артефакты + `.minisig` выкладываются в
GitHub Release; сервер тянет и проверяет `minisign -V` публичным ключом отсюда.
