## [Unreleased]

Клиентское приложение (треки **C0–C4**, см. `docs/CLIENT-ARCH.md`): движок выделен во
встраиваемую библиотеку, добавлены формат клиентских кред, десктоп-клиент (Linux) с GUI,
привилегированным TUN и зашифрованным хранилищем профилей, Android-клиент через `VpnService`
и разворачивание exit-сервера подписанным скриптом-инсталлером (admin, supply-chain через minisign).
**90 unit-тестов, Docker 15/15, `clippy --workspace --all-targets -D warnings` чисто; APK собирается,
Android-коннект подтверждён на эмуляторе, exit развёрнут инсталлером на боевом VDS.**

### Добавлено
- **C0 — ядро-как-библиотека.** Движок вынесен из бинаря `citadel-m1` в библиотечные модули
  `citadel_quic::{config,dataplane,client,vpn}`:
  - `TunIo`-трейт (абстракция туннеля) + `Tun::from_raw_fd` — платформенный TUN инъектируется
    (Android `VpnService` fd и т.п.);
  - `ClientConfig` + `from_env()` — движок конфигурируется структурой, не окружением;
  - `establish_session` / `run_data_plane` — разделение «адрес → TUN» (порядок для мобильных ОС);
  - `VpnController` (`connect`/`disconnect`/`subscribe()` события `Connecting/Up/Down`) + трейт
    `TunProvider` (платформа туннеля за абстракцией);
  - крейт **`citadel-client`** (`cdylib`/`staticlib`) — FFI-вуаль для GUI; кросс-собирается под
    `aarch64-linux-android` (aws-lc-rs + PQ-крипта под Android NDK — риск R1 снят).
- **C1 — формат кредов** (`citadel_client::creds`):
  - `CredentialBundle` — полный набор кред (CBOR, файл `.citadelconf`);
  - `CredentialLink` — компактная `citadel://`-ссылка/QR: большие публичные ключи → обязательства
    `H(pub)` (CRQC-safe bootstrap), секреты инлайн; генерация QR (`to_qr_svg`) — компактная
    ссылка влезает в QR версии 18 (545 B против ~2.4 КБ полного бандла);
  - `to_client_config()` — `CredentialBundle` → `ClientConfig` (`PinSource::Bytes`/`MldsaSource::Bytes`).
- **C2 — десктоп-клиент (Linux):** GUI на Flutter + flutter_rust_bridge поверх `citadel-client`.
  - **Привилегии через polkit:** `citadel-helper` (root по `pkexec`) создаёт TUN + настраивает
    адрес/маршруты/DNS и передаёт fd приложению по `SCM_RIGHTS`; непривилегированный GUI крутит
    data-plane (`GuiTunProvider`). Polkit-политика + `tools/install-desktop.sh`.
  - **GUI** (connection-centric): подключение по `citadel://`-ссылке/профилю, поток событий
    состояния (карточка статуса с таймером сессии), мультипрофильность, диалог переключения.
  - **Vault** (`citadel_client::vault`) — зашифрованное хранилище профилей: мастер-пароль →
    PBKDF2-HMAC-SHA256 → AES-256-GCM (aws-lc-rs, кроссится под Android); профиль сохраняется
    после первого успешного подключения; выбор/удаление/смена пароля.
  - **Тестовый стенд:** QEMU/KVM VM (`tools/qemu-testvm.sh` — Debian-13/xfce/startx, 9p-шара,
    общий буфер обмена через spice-vdagent) + token-less E2E-exit с публикацией портов
    (`docker/compose.e2e.yml`, `run-e2e-exit.sh`) + генератор ссылок (бинарь `citadel-linkgen`).
- **C3 — Android-клиент (`VpnService`):** мобильный путь поверх того же движка/FFI.
  - Двухфазное подключение (мобильный порядок «адрес → TUN»): `android_establish` (PQ-хендшейк
    + назначение адреса, без TUN) → Kotlin `VpnService.Builder.establish()` → fd → Rust
    `android_run_data_plane` (data-plane + поток событий). `citadel_tun::Tun` (fd-путь) расширен
    на Android.
  - **Анти-петля `protect()`:** хук `citadel_quic::protect` (`SocketProtector` / `protect_socket`)
    в движке + JNI-мост (`android_jni.rs` ↔ `CitadelVpnService.protectFd`) — исходящие сокеты
    движка исключаются из собственного туннеля.
  - `CitadelVpnService` (foreground) + MethodChannel + Dart-ветка `Platform.isAndroid` в UI.
- **C4 — Admin-deploy (разворачивание сервера скриптом):** первая установка exit — standalone
  bootstrap на сервере (без GUI): авто-Docker (с проверкой запущенности демона) → скачивание
  **подписанного** бинаря с GitHub Release + проверка `minisign` и SHA-256 (supply-chain) →
  серверный keygen → `docker compose up` → печать админской `citadel://`. Инструменты:
  `tools/{gen-release-key,mk-release,publish-release,install-citadel-server}.sh`, бинарь
  `citadel-linkgen` (генерация ссылки на сервере). `citadel-client` получил модуль `deploy`
  (`AdminDeployer` на `russh` — задел под GUI-remote-deploy, десктоп-only). Подтверждено на боевом VDS.
- **Инфраструктура разработки:** `tools/setup-dev-env.sh` — идемпотентный установщик окружения
  (rustup, Android NDK/SDK, Flutter, кросс-таргеты); `tools/requirements.txt`.

### Изменено
- `pump` (data-plane) работает поверх `Arc<dyn TunIo>` вместо конкретного `Tun`.
- `pump`: **отменяемый TUN-reader** (`poll` + stop-флаг) — на disconnect интерфейс/fd корректно
  закрываются (чинит «не переподключается до перезапуска»); попутно закрыта серверная гонка
  чтения общего TUN при multi-client.
- Exit: **MSS-clamp** (`TCPMSS --clamp-mss-to-pmtu`) — анти-PMTUD-блэкхол, иначе TCP/HTTPS сквозь
  туннель виснет (ICMP идёт). Пул адресов конфигурируем из `Citadel_TUN_ADDR` (база/префикс,
  готов к /16).
- Весь workspace приведён к чистоте `clippy --all-targets -D warnings` на тулчейне Rust 1.96.
- `citadel-tun`/`citadel-client` компилируются и под `target_os = "android"` (fd-путь TUN,
  `gui_tun`/`sendfd`; `ioctl`-request `c_int`/`c_ulong` для bionic/glibc).
- cargokit/rust_builder адаптированы под Gradle 9.1 / AGP 9.0.1 (инжект `ExecOperations` вместо
  удалённого `Project.exec()`, rustup-тулчейн в PATH сборки, `compileSdk` 36).
- Docker-демо (`entrypoint-client.sh`): устранены флаки оркестрации (probe по IP под DNS-lock;
  снятие UDP-блока после TCP-fallback теста; `wait` предшественника + retry в тестах с рестартом).
- **Клиент:** профиль сохраняется в хранилище **сразу при добавлении** (раньше — только после
  первого успешного подключения → терялся при неудаче); ненужный конфиг удаляется вручную.

### Исправлено (2026-07-27)
- **Консольный клиент: «подключается, но интернета нет» (GUI на той же машине работал).** Корень —
  в последней ступени лестницы резолвера («заворот всего `:53` в туннель»), которая включается,
  когда `/etc` только для чтения. У GUI её не бывает: его helper запускается через polkit **без
  песочницы**, поэтому там проходит обычная запись `/etc/resolv.conf`. Ступень не работала вовсе,
  по двум независимым причинам:
  - `-o` в `filter OUTPUT` после `DNAT` **врёт**: netfilter вычисляет выходной интерфейс до прохода
    хуков `OUTPUT`, и хотя ядро перемаршрутизирует завёрнутый пакет в туннель, правила того же
    прохода видят прежний, физический интерфейс. Завёрнутый DNS не совпадал с `-o citadel0 -j
    RETURN` в `CITADEL_KS` и умирал в нашем же финальном `DROP` (сколько пакетов заDNATилось —
    столько же и дропнулось). Рубеж `:53` перенесён в **`mangle POSTROUTING`**, где интерфейс
    фактический; `CITADEL_KS` выпускает `:53` без проверки интерфейса, но только когда этот рубеж
    поставлен (`dns_guarded`). Проверка стала строже — ловит любой `:53` мимо туннеля.
  - `DNAT` меняет назначение, но **не источник**: адрес выбирался по маршруту к первоначальному
    резолверу (адрес локалки) и сохранялся при перемаршрутизации, а exit обязан дропать такой
    inner-src анти-спуфингом (S0.2/H3) — ответа не было бы никогда. Добавлена цепочка
    `CITADEL_DNS_SNAT` (`MASQUERADE` для `:53` к резолверу туннеля на его интерфейсе); conntrack
    разворачивает и DNAT, и SNAT, поэтому приложение видит ответ от того резолвера, о котором
    спрашивало.
  Плюс порядок правил: цепочка сначала подвешивается в хук и лишь потом наполняется — иначе
  `iptables-legacy` не примет `DNAT`/`MASQUERADE` в «висящей» цепочке (на nft-бэкенде проверки нет,
  и дефект был бы «работает у меня, не работает у него»).
- **Диагностика вместо загадки.** Клиентский `pump` считает inner-пакеты, ушедшие в туннель с src,
  который exit'ом нам не назначен (он дропает их молча — на клиенте это «отправлено много, принято
  0»), и в окне watchdog называет число, последний такой адрес и назначенный нам. По адресу видно
  природу: локалка — заворот без SNAT, `127.0.0.1` — петлевой bind, адрес другого интерфейса —
  приложение прибито к нему явно. Демон, получив `EROFS` на `/etc/resolv.conf`, отдельно объясняет
  причину: если юнит **на диске** разрешает запись, а у процесса `/etc` только для чтения — значит
  работает старая песочница, и печатается готовая команда (`daemon-reload && restart`).
- **Иконка Linux-GUI не менялась в меню и на рабочем столе.** `gtk-update-icon-cache` без `-f`
  отказывается работать в теме без `index.theme` и оставляет **старый** `icon-theme.cache`, а GTK
  при наличии кеша файлы на диске уже не читает. Оба установщика теперь делают
  `gtk-update-icon-cache -f -t`, `xdg-icon-resource forceupdate`, `update-desktop-database` и
  пересборку KDE-кеша, ставят запасную копию в `/usr/share/pixmaps` и прописывают в `.desktop`
  `StartupWMClass=com.quantumaes.citadelpqvpn` — без него панель/док показывали запущенному окну
  generic-иконку, хотя в меню она уже была брендовой.

### Исправлено (2026-07-26, вторая сессия)
- **Обновление консольного клиента не доезжало до работающего демона.** Оба установщика
  (`tools/install-cli.sh` и `install.sh` внутри релизного тарбола) заканчивались на
  `systemctl enable --now`, но `--now` на **уже активном** юните — no-op, а `daemon-reload` не
  перечитывает песочницу живого процесса. После апгрейда файлы на диске были новые, а в памяти
  оставался прежний демон: со старым кодом и старым `ProtectSystem` без `ReadWritePaths=/etc`.
  Наружу это выглядело как «давно исправленный баг вернулся» — сессия падала на
  `записать /etc/resolv.conf: Read-only file system`, хотя и лестница резолвера, и фикс юнита
  лежали на машине. Теперь установщики делают безусловный `systemctl restart` (сессию он рвёт
  чисто: по SIGTERM демон снимает kill-switch).
- **`citadel-cli` сам обнаруживает устаревший демон.** Демон сообщает время своего старта
  (`StatusInfo.daemon_started_unix`, `serde(default)` — ответ демона прошлой версии читается
  по-прежнему), клиент сравнивает его с mtime `/usr/lib/citadel-pqvpn/citadel-vpnd` и предупреждает
  в `status`, `version`, в шапке TUI и перед `connect`: «работает УСТАРЕВШИЙ демон» с готовой
  командой лечения. Класс ошибки «чиню не то, что запущено» перестаёт быть невидимым.
- **Пул адресов exit'а не выдаёт адрес шлюза при подсети шире `/16`.** Пул считал шлюзом «сеть+1»
  — верно для `10.7.0.1/16`, но при расширении до `10.7.0.1/12` сеть становится `10.0.0.0/12`, а
  шлюз (он же `ADMIN_VIP` admin-канала) оказывается в её глубине и достался бы очередному клиенту:
  коллизия адресов с самим exit'ом. Теперь исключается фактический host-индекс шлюза.
  Заодно исчерпанный пул отвечает отказом сразу, не прочёсывая host-пространство под общим
  мьютексом (на `/12` это миллион итераций на каждый коннект — готовая точка отказа).

### Изменено (2026-07-26, вторая сессия)
- **Внутренняя сеть туннеля — `/16`** (`10.7.0.1/16`, NAT `10.7.0.0/16`) во всех дефолтах: раньше
  установщик сервера уже ставил `/16`, а дефолты `citadel-m1` и docker-стенд остались на `/24`, то
  есть стенд проверял не ту конфигурацию, что едет в прод. Схема адресации рассчитана с запасом на
  расширение до `/12` (тест на выдачу адреса шлюза в такой сети — в `citadel-m1`).
- **Журнал сессии в TUI прокручивается**: `PgUp`/`PgDn` страницей, `Shift+↑↓` построчно,
  `Home`/`End` к краям, `f` — автопрокрутка (включена по умолчанию; выключается сама при
  прокрутке вверх и включается при возврате вниз, как `journalctl -f`). Строки переносятся с
  подсчётом фактических экранных строк, поэтому длинные сообщения об ошибках не сбивают позицию.
- **Linux GUI: вернулась кнопка «свернуть».** Она пропала из-за `setMaximizable(false)`: в
  `window_manager` под Linux этот вызов сделан через `GDK_WINDOW_TYPE_HINT_DIALOG`, то есть окно
  объявлялось диалогом, а диалогу WM рисует только «закрыть». Убрать одну кнопку, не задев другую,
  этим API нельзя (`setMinimizable` дёргает тот же type hint), поэтому на Linux вызов больше не
  делается — размер окна и так фиксирован `setResizable(false)`.
- **Иконки всех клиентов обновлены** из `app_icons/` новым инструментом `tools/sync-app-icons.py`
  (идемпотентный, `--check` для CI). Android-`ic_launcher_foreground` **генерируется**, а не
  копируется: на Android 8+ система показывает adaptive-слой, и подмена одного легаси-PNG оставила
  бы на современных телефонах старую иконку. Цвет фона под маской берётся из мастер-арта.

### Изменено (UX, 2026-07-26)
- **Linux GUI больше не спрашивает пароль на каждое подключение.** polkit просил подтверждение не
  только на первое поднятие туннеля, но и на **каждый автоматический реконнект** (реконнект = новый
  запуск хелпера через `pkexec`). Установщик ставит правило
  `/etc/polkit-1/rules.d/49-citadel-pqvpn.rules`: членам группы `citadel-vpn` — без пароля (та же
  модель авторизации, что у консольного клиента, где право даёт доступ к сокету демона); всем
  остальным — как раньше. Отключается `install-desktop.sh --ask-password`; в группу установщик
  никого не добавляет сам (`--user ИМЯ` — по явной просьбе).
- **Вместо технического текста ошибки — «Сервер недоступен» и профиль**, к которому пытались
  подключиться (GUI, TUI и `citadel-cli status`). Полная цепочка причин (`{e:#}`) целиком уходит в
  журнал отладки — добавлено логирование там, где событие `Error` его не имело. Отказ в разрешении
  на VPN (Android) остался отдельным сообщением: это действие пользователя, а не недоступный сервер.
- **Справка по клавишам в TUI** — экран по `?`/`h` (на экранах ввода, где `?` — часть пароля или
  ссылки, F1) со всеми клавишами по экранам; там же названо главное, чего не видно по интерфейсу:
  выход из TUI не разрывает туннель, сессию держит демон.
- **Windows: закрытие окна при активном туннеле уходит в трей молча**, без диалога «фон / отключить»
  (выйти по-настоящему — «Выход» в меню трея). Убрана кнопка «развернуть»: размер окна фиксирован.
- **Экран мастер-пароля показывает фирменный логотип** (тот же рисунок, что иконка приложения)
  вместо material-иконки.
- Подсказка в UI split-туннеля объясняет **что происходит с DNS**: приложения в туннеле резолвят
  через резолвер туннеля, остальные — через DNS сети (провайдер видит их домены); системный
  «Личный DNS» (DoT) применяется и внутри туннеля.
- `citadel-helper` (GUI-путь) отвергает `--bypass` шире `/8` — та же граница охвата, что в
  `citadel-vpnd`: более широкое «в обход» гасит kill-switch при включённом индикаторе защиты.

### Исправлено
- **Android: создание хранилища падало ложным «Неверный пароль».** Путь vault резолвился из
  `XDG_CONFIG_HOME`/`HOME`, которых в песочнице Android нет → файл уходил в недоступную для записи
  директорию, `Vault::create` падал, а диалог трактовал любую ошибку как неверный пароль. Каталог
  данных теперь задаёт платформа (`set_data_dir` ← `getApplicationSupportDirectory()`, Android
  `filesDir`); десктоп по-прежнему использует `XDG`/`HOME`. Диалог создания хранилища показывает
  реальную причину ошибки вместо «неверного пароля».
- **Бесконечное переподключение на мобильной сети** (Android/cellular; проявлялось как «не
  открывается список абонентов»). Четыре сцепленных дефекта:
  - `pump`-watchdog рвал **живой** транспорт: «нет обратных датаграмм» трактовалось как мёртвый
    путь, хотя ACK'и/keep-alive шли. Теперь разрыв только при отсутствии и QUIC-пакетов от пира
    (`stats().udp_rx`); иначе — диагностическая строка (дельты, RTT, MTU пути).
  - Эскалация QUIC→obfs-TCP срабатывала на ЛЮБУЮ ошибку establish: жгла второй Layer-1 токен и
    подменяла настоящую причину бесполезным `auth-failed`. Теперь — только транспортные отказы
    (`should_escalate_to_tcp`), причина QUIC-попытки доклеивается к итоговой ошибке. Это же
    вернуло два молча сломанных docker-негатива (ТЕСТ 15 PQ-auth, ТЕСТ 19 commitment-fetch).
  - Потраченный токен предъявлялся повторно, если issuer не выдал свежий (недоступен либо держит
    single-session-аренду) → гарантированный `auth-failed` по кругу. Теперь попытка не делается.
  - Причина отказа терялась: диагностика печатала `{e}` вместо `{e:#}` (у quinn причина — в
    `source`), в UI приходило бесполезное «read error: connection lost».
- **MTU-инварианты data-plane** (латентные, задокументированы в `docs/CLIENT-ARCH.md §15`):
  паддинг obfs больше не раздувает пакет выше `MAX_QUIC_PACKET + FRAMING_OVERHEAD` (`WIRE_CAP`,
  1255) — иначе полноразмерные пакеты чёрнодырились на узких путях (мобильные/NAT64/GTP) при
  живом хендшейке; MTU туннеля exit'а и клиента приведены к одному числу `INNER_MTU` (1161 =
  бюджет QUIC-датаграммы). Формат провода не изменён — не wire-break; exit подхватывает после
  рестарта с `Citadel_MTU=1161`.
- Клиентский `pump` дропает не-IPv4 локально (в TUN Android намеренно `::/0`-blackhole, S2.2/A2):
  раньше этот трафик кормил ложное срабатывание watchdog.
- **Консольный клиент не поднимал туннель: «записать /etc/resolv.conf: Read-only file system».**
  Корень — в собственном юните: `ProtectSystem=full` делает read-only не только `/usr` и `/boot`,
  но и **`/etc`** (комментарий в юните утверждал обратное). Добавлен `ReadWritePaths=/etc`
  (точечный `ReadWritePaths=/etc/resolv.conf` не годится: systemd делает bind-mount самого файла,
  после чего его нельзя ни заменить, ни удалить). Туннель при этом уже стоял — сессию валила
  именно настройка резолвера.
- **Резолвер (F6) больше не единственная точка отказа.** Способ настройки выбирается лестницей
  (`docs/LINUX-CLI.md` → «Резолвер (F6)»): запись `/etc/resolv.conf` → `resolvectl`
  (systemd-resolved, с проверкой, что он и есть резолвер системы) → `resolvconf` → принудительный
  заворот всего `:53` в туннель (`iptables -t nat`, цепочка `CITADEL_DNS`). Fail-closed не
  ослаблен: F6-правила ставятся при любом способе, а если не сработал ни один — `TunSetup`
  по-прежнему отвергается. Для способов со stub-резолвером дополнительно разрешён `:53` на `lo`.
- **`/etc/resolv.conf` теперь подменяется атомарно** (временный файл + `rename`): не остаётся окна
  «резолвера нет вообще» и не портится цель симлинка systemd-resolved. Где `rename` невозможен
  (bind-mount в контейнерах даёт `EBUSY`) — запись «на месте», но только для обычного файла.
  Резолвер создаётся с правами 0644 явным `chmod`: при `UMask=0077` демона он получался root-only.
- **F6-правила копились на реконнектах.** `dns_rules` добавлялись на каждый `TunSetup`, а
  снималась одна копия: после сессии с реконнектами в `OUTPUT` оставались `DROP` на `:53` к уже
  мёртвому интерфейсу — DNS не работал и после отключения (тот же класс, что залипший
  kill-switch). Теперь перед установкой правила снимаются; e2e проверяет, что после disconnect
  правил `:53` не осталось ни одного.
- **Метка профиля не терялась при аварийном разрыве** — демон переносит её в «пустой» статус,
  иначе клиент не мог сказать, к чему не удалось подключиться.
- **Android: не добавлялся маршрут к резолверу туннеля.** При split по назначениям (include, либо
  exclude, накрывающий резолвер) DNS-сервер оказывался вне туннеля и приложения под VPN не
  резолвили ничего. Kotlin добавляет `addRoute(<dns>/32)` — тот же инвариант, что host-route на
  DNS в `citadel-vpnd`.

### Безопасность
- **No-logs на серверных ролях** (`docs/SECURITY-ROADMAP.md §8`). Exit и issuer писали в
  `docker logs` связку «IP клиента ↔ `client_id` ↔ время ↔ **назначения пакетов**» — из такого
  журнала unlinkability анонимных токенов восстанавливалась тривиально. Теперь всё
  идентифицирующее пишется только при явном `Citadel_DEBUG_LOG=1` (`citadel_quic::dlog!` /
  `citadel_token::dlog!`); из текстов ошибок Layer-1 убран адрес пира. Демо/e2e-стенды ставят
  флаг явно, прод-шаблон `AdminDeployer` — нет.
- Диагностика клиента: шаг **«Admin-канал»** — сырой TCP-SYN на `ADMIN_VIP:порт` прямо в туннель,
  мимо ОС-роутинга; отделяет поломку на exit'е от поломки маршрута/split на устройстве.

### Релиз
- `tools/mk-client-release.sh` собирает и упаковывает **консольный клиент Linux** (трек L):
  `citadel-cli-linux-<arch>.tar.zst` = `citadel-vpnd` + `citadel-engine` + `citadel-cli` +
  systemd-юниты + самодостаточный `install.sh` (без cargo и исходников на целевой машине).
  Флаг `--no-cli` пропускает сборку.
- Трей Windows показывает состояние туннеля цветной точкой-бейджем на значке (+ tooltip с
  текстом состояния); окно приложения — 400×680.

## [0.1.0] — 2026-06-22

Первый публичный **PoC-релиз**. Вся дорожная карта `SPEC.md §12` (M0–M7) закрыта на уровне
proof-of-concept: **49 unit-тестов, 15 Docker-сценариев, 0 предупреждений компилятора**.

### Добавлено
- **M0** — гибридный PQ-QUIC хендшейк `X25519MLKEM768` (quinn + rustls/aws-lc-rs).
- **M1–M2** — CONNECT-IP туннель поверх QUIC DATAGRAM, динамический адрес (`ADDRESS_ASSIGN`),
  NAT; pinning сертификата (F1), egress-фильтр (F2), сброс привилегий до nobody (F4),
  DNS-leak protection + DoH (F6).
- **M3** — обфускация L1 (PSK-gated ChaCha20-Poly1305) → probe-resistance (F3), анти-DPI (F5);
  анти-fingerprint по размеру (bucketed padding) и по времени (DAITA-пейсинг + chaff) — ось I5.
- **F7** — per-client token-bucket rate-limit на exit (анти-абуз).
- **M4** — TCP/443-fallback (obfs-over-TCP при блокировке UDP/QUIC) + миграция соединения
  (QUIC connection migration: WiFi↔LTE / NAT-rebind).
- **M5** — анонимные токены (blind RSA, RFC 9474) + интерактивный issuer↔exit split (слепое
  подписание) + выбор exit из списка с failover.
- **M6** — robustness-fuzzing парсеров недоверенного ввода, criterion-бенчмарки
  (`docs/BENCHMARKS.md`), кеш KDF/cipher в hot-path (−15% на мелких пакетах), crypto-agility
  (именованный выбор KX-suite, TLS-negotiate).
- **M7** — PQ-аутентификация: гибрид Ed25519 (TLS-cert + pin) + **ML-DSA-65** (FIPS 204).

### Безопасность
- Никаких секретов в репозитории: общий obfs-PSK, RSA-ключ издателя, ML-DSA-ключ exit и pin
  сертификата генерируются в рантайме (Docker-том), не версионируются.

### Известные ограничения
- Исследовательский PoC — **не проходил независимый аудит**, не для production.
- obfs-over-TCP — псевдослучайный поток на :443 (не TLS-mimicry) → слабее против цензора,
  валидирующего TLS на :443.
- coverage-guided fuzzing требует nightly toolchain (сейчас — robustness-тесты на stable).
- Backlog (полировка, не этапы): TLS-mimicry/Reality, полный kill-switch, h3 Extended-CONNECT,
  latency-based выбор exit, ротация токенов на клиенте. См. `docs/SPEC.md §12`, `THREAT-MODEL §4`.
